# 研究中心（/research-center）组件设计记录

执行合同：研究中心只聚合已经持久化的个人研究状态，不新增自动写入。复核紧迫度不是投资排名，研究行动不是交易信号，历史结果只用于检查原研究条件，任何正式判断、任务、计划或复盘仍需用户明确确认。

## 数据合同

| 模块 | 接口 | 页面用途 |
| --- | --- | --- |
| 优先处理 | `GET /me/research-priority` | 按复核紧迫度整理关注标的，展示排序口径和下一次复核重点 |
| 研究变化 | `GET /me/research-changes?limit=30` | 回读连续研究报告中已归档的证据变化 |
| 当前行动 | `GET /me/research-actions` | 展示已触发、待补证和持续观察的核验动作 |
| 补证任务 | `GET /me/evidence-tasks?limit=50` | 回读正式研究对话产生的资料缺口及处理状态 |
| 结果复盘 | `GET /me/research-outcomes?limit=120` | 展示 T+3/T+5/T+10 研究条件的到期或进行中结果 |
| Run 复盘 | `GET /me/run-reviews?days=30&limit=30` | 回读正式顾问对话的回答摘要、证据覆盖和回答检查状态 |

六个查询使用独立 query key、独立 loading/error/empty/retry 状态；任何单接口失败只降级对应模块，不清空整页。接口原始状态在 adapter 中保留，展示层统一翻译为中文；未知状态显示“状态待确认”，不直接暴露内部枚举，也不猜测其含义。

## 页面结构与互动

- 概览区只显示六个合同返回的真实计数，缺字段显示 `--`，`0` 保持为有效值。
- 优先处理和当前行动位于首屏；变化、补证、结果和 Run 复盘按研究过程继续向下排列。
- “查看个股研究”“问顾问”“打开原对话”只做跨页导航，不在研究中心自动创建正式记录。
- “刷新研究状态”显式重取六个模块；刷新期间禁用按钮，避免重复操作。
- 新账户显示六个真实空态，不用演示股票、示例收益或伪造 Run 填充页面。
- 390px 下所有网格折为单列，表格或长文本不得造成页面根级横向溢出。

## 边界

- `priority_score` 的名称固定为“复核紧迫度”，不可改写成综合评分、机会排名或收益预期。
- T+3/T+5/T+10 价格变化只说明研究条件后的客观路径，不证明原逻辑正确，也不评价荐股准确率。
- 补证任务的“已解决”只表示资料处理完成，不表示投资结论成立。
- Run 复盘中的回答检查是产品质量信息，不作为页面主目标，也不增加新的全局 Guard。

## 验收

- 单元测试：adapter 合同解析、未知合同拒绝、正常态、空态、单模块失败、显式刷新和未登录不请求。
- Playwright 合同：六接口正常态、真实空态、单模块失败、三类跨页链接、390px 根级无横向溢出。
- 真实 E2E：隔离账户与 Schema 中建立真实关注/研究/Run，再验证页面回读、刷新恢复、窄屏、控制台错误与失败请求。
