# 个人中心研究工作台设计

日期：2026-07-25
产品：清数智算
范围：个人中心页面、个人中心聚合接口及相关测试

## 1. 目标

将当前个人中心从虚构会员与账户展示页改为当前用户的研究工作台。页面只回答三个问题：

1. 当前有哪些需要继续处理的研究事项。
2. 用户已经积累了哪些关注、研究、持仓与复盘资产。
3. 用户可以从哪里继续完成投资研究闭环。

页面不承担账户设置、支付、会员、积分或自建 API 管理职责。

## 2. 设计原则

- 以现有 HTML 的蓝白配色、卡片比例、圆角、间距和桌面两栏结构为视觉基准。
- 不新建独立设计体系，不大规模改写前端技术栈。
- 所有数字和列表必须来自当前用户的持久化数据。
- 不使用静态示例冒充实时数据或用户资产。
- 没有数据时显示明确空状态和可执行入口，不显示虚构的零收益或默认结论。
- 状态同时使用文字、图标或形状表达，不只依赖红绿颜色。
- 个人数据按当前登录用户隔离；接口不得返回其他用户的数据。

## 3. 信息架构

### 3.1 顶部四张概览卡

保留原 HTML 顶部四卡结构，内容替换为：

1. 待处理事项
   - 进行中研究
   - 失败或等待重试的研究
   - 待复盘交易
   - 其他能够从现有持久化状态确定的待办
2. 我的关注
   - 当前关注数量
   - 最近更新数量或最近更新时间
   - 进入“我的关注”
3. 研究资产
   - 研究案例或研究运行总数
   - 进行中与已完成数量
   - 进入“AI 研究”
4. 持仓与复盘
   - 当前持仓数量
   - 已记录交易数量
   - 待复盘数量
   - 进入“复盘管理”

不计算或展示后端尚未可靠提供的触发数量、收益率、会员额度或积分。

### 3.2 主区域左栏

左栏承担主要工作流：

- 优先待办：按失败研究、进行中研究、待复盘交易等确定性优先级排序。
- 最近研究任务：显示证券、研究问题摘要、执行状态、更新时间和继续入口。
- 最近关注变化：显示最近加入或更新的 A 股关注项。

每个列表设置数量上限，避免无分页加载全部历史记录。

### 3.3 主区域右栏

右栏保留原 HTML 辅助栏比例，改为：

- 投资闭环进度：关注、研究、持仓、复盘四个阶段的真实资产计数。
- 快捷入口：去关注、开始研究、查看持仓、开始复盘。
- 数据说明：显示数据截止时间及“仅包含当前用户数据”的边界说明。

## 4. 数据契约

继续使用现有 `GET /api/v1/me/profile-summary`，采用兼容扩展，不删除当前字段。

新增 `workbench` 对象，建议结构：

```json
{
  "generated_at": "ISO-8601",
  "summary": {
    "pending_count": 0,
    "watchlist_count": 0,
    "research_total": 0,
    "research_running": 0,
    "position_count": 0,
    "trade_count": 0,
    "review_pending_count": 0
  },
  "todos": [],
  "recent_research": [],
  "recent_watchlist": [],
  "lifecycle": []
}
```

约束：

- 聚合查询必须带 `user_id`。
- 列表默认最多返回 5 条。
- 研究状态沿用现有任务状态契约，不在前端自行推断。
- 待复盘数量只能由已持久化交易和复盘状态确定；无法确定时不展示该细分数字。
- 接口异常时返回明确错误，前端显示重试入口，不回退到静态假数据。
- 原有 `research_assets` 字段暂时保留，供旧调用方兼容。

## 5. 前端组件与状态

个人中心仍由现有单页应用加载，但静态 HTML 中不再保留虚构会员、积分、API 和账户信息作为首屏占位。

页面状态：

- `loading`：显示与最终布局一致的骨架卡片。
- `ready`：渲染真实聚合数据。
- `empty`：显示研究闭环说明及四个真实入口。
- `partial`：部分列表失败时保留已成功的概览数据，并在对应区域提示失败。
- `error`：显示个人工作台加载失败、重试按钮和返回今日页入口。

不得通过整段 `innerHTML` 在加载后覆盖一套完全不同的静态页面。个人中心使用稳定容器和独立渲染函数更新内容。

## 6. 删除内容

从消费者页面彻底删除：

- 尊享会员、会员有效期和会员权益。
- 积分余额、今日积分和积分明细。
- API 调用次数、自建 API 表格及操作按钮。
- 虚构手机号、邮箱、微信、密码和实名认证。
- 联系手机号编辑。
- 支付宝订单草稿和相关操作。
- “后端聚合接口”等内部实现文案。

相关后端接口本轮不删除，以避免破坏其他调用方；只从个人中心移除入口。后续确认无调用方后再独立下线。

## 7. 响应式布局

### 1440×900

- 顶部四卡保持单行。
- 主区域为左侧主内容、右侧辅助栏。
- 第一屏应能看到四张概览卡和至少一组优先待办。
- 不允许表格或长文本撑破卡片。

### 390×844

- 概览卡改为单列或两列紧凑布局，重要待办卡优先。
- 主区域改为单列。
- 快捷入口按钮至少具备 44px 可点击高度。
- 研究问题摘要使用有限行截断。
- 不出现横向页面滚动；需要横向内容时改为卡片列表。

## 8. 错误处理与安全

- 未登录时沿用现有 401 会话处理。
- 用户只能看到自己的关注、研究、持仓和交易。
- 页面不得显示工作区物理路径、会话令牌或供应商凭证。
- 接口和页面不输出支付、会员或 API 能力的占位操作。
- 对失败研究显示可理解状态，不展示内部异常堆栈。

## 9. 测试与验收

自动测试至少覆盖：

- 两个用户的工作台数据严格隔离。
- 研究状态数量和待办映射正确。
- 当前持仓、交易与复盘数量口径正确。
- 无数据时返回空列表而非假数据。
- 前端源码不存在会员、积分、自建 API、支付宝订单草稿和账户资料入口。
- 前端使用新的 `workbench` 契约并保留加载、空、部分失败和错误状态。

人工验证：

- 1440×900 检查卡片、待办、最近研究和右栏。
- 390×844 检查导航、单列布局、按钮和长文本。
- 验证个人中心与关注、AI 研究和复盘页面跳转。
- 验证刷新页面时不闪现旧的虚构会员页面。

## 10. 兼容、迁移与回滚

- 数据库不新增表；优先复用现有关注、研究任务、持仓和交易结构。
- `profile-summary` 采用新增字段方式兼容旧调用方。
- 前端异常时不回退旧静态个人中心。
- 回滚时可以恢复旧前端渲染，但不得恢复虚构会员、支付或 API 内容。

## 11. 非目标

- 不建设正式会员、积分或支付系统。
- 不建设自建 API 管理。
- 不新增账户资料和实名认证功能。
- 不新增券商连接。
- 不新增研究、持仓或复盘领域模型。
