# 正式前端运行与数据合同收口设计

## 目标

在开始任何视觉重做前，建立唯一可复现的正式运行基线，并让今日观察、透明选股和老李策略只展示有明确来源、频率、交易时点与新鲜度状态的真实数据。

## 范围与顺序

1. **运行基线**：正式 worktree `formal-six-page-ui` 是唯一候选源码；开发、生产与浏览器验收均显式记录 commit、后端地址和前端地址。旧 Vite 不再作为验收依据。
2. **行情新鲜度合同**：区分实时 Quote、日线 Bar、研究/筛选 Snapshot。每个模块返回来源、市场时点、抓取时点、粒度和 `fresh/stale/unavailable` 状态；过期缓存只能作为带 `stale` 标识的回退。
3. **请求生命周期**：所有前端请求有统一的超时、取消、错误分类和有限重试。慢速或不可用的二级模块不能阻塞首屏。透明选股请求只读已经发布的市场快照，绝不在用户请求中触发全市场 TeaJoin 扫描。
4. **视觉实现**：仅在前三项通过真实环境验证后，重做 AppShell、今日观察首屏和透明选股三模式的桌面与 390px 布局；最后才添加图表与动效。

## 数据源合同

- TeaJoin 的 Tushare 兼容接口用于 A 股日线、估值、财务、股东和筛选/策略快照。它的 `daily` 是日终数据；交易时段没有当日完整 Bar 时必须返回空或上一完整交易日，不能标为实时。
- 腾讯实时指数 Quote 可用于五指数卡，但必须明确 `realtime_quote` 和时间戳；对应 Sparkline 使用独立日线历史。
- 东方财富/新浪等仍存在的公共市场模块必须各自暴露来源与新鲜度；不能因 TeaJoin 已接入就伪称全站同源。
- TeaJoin 客户端必须真正应用连接/读取超时、有限退避和供应商错误分类。凭据只来自进程环境，绝不进入源码、测试 fixture、日志或 Git。

## 透明选股与老李边界

- 通用筛选只读取 `stock_screen_market` 的已发布稳定快照；没有稳定快照时快速返回可解释的 `snapshot_not_ready`，由后台任务刷新。
- 老李全市场结果只有在宇宙快照稳定、覆盖率达标且深度核验完成时才可称为全市场结果。部分进度只显示进度/数据不足，不能展示为完整候选结论。
- 页面显示的每一条候选必须可回溯到快照版本、市场日和规则证据；缺失值不转换为零或“通过”。

## 验收门禁

- 候选运行记录固定 commit、worktree、后端地址、数据库 schema 和构建产物来源。
- `TUSHARE_TOKEN` 已配置且 TeaJoin 最小读查询成功；未配置或上游失败时不泄漏供应商细节。
- 不存在用户触发的全市场同步；透明选股在无快照时有界失败，不无限等待或重试。
- 实时、日线和快照数据的时点标签正确，过期数据统一标为 `stale`。
- 当前阶段未通过这些门禁前，不进行 UI 验收，也不创建正式前端基线。

## 回滚

所有改动采用兼容字段和后台快照优先策略：若新提供商或新鲜度合同失败，保留已发布的稳定快照并标记 `stale` 或 `unavailable`；不删除旧静态文件、不变更认证合同、不直接修改生产数据。
