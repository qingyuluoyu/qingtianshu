# High-fidelity 前端后端对齐设计

日期：2026-07-23

## 目标与范围

以 `app/static/high-fidelity-demo.html` 和 `app/static/high-fidelity-demo.js` 为唯一前端契约，按页面顺序接通正式后端数据。保留既有页面和既有接口兼容性，不将演示数字、投资建议或未授权外部内容伪装成金融事实。

本轮交付五个垂直工作包：今日观察、个股评分库、AI 研究与我的关注、研究复盘与个人中心、静态演示与接口契约清理。

## 架构与接口策略

继续使用现有 FastAPI、SQLite 和服务层。新增能力以窄的 `/api/v1` 适配路由和独立领域服务承载；路由只做认证、输入验证、错误映射和响应转换，金融计算、数据标准化和数据访问留在服务层。

现有以下路由保持兼容并作为第一页切片基础：市场总览、指数报价、涨跌结构、行业轮动、热门主题、成交活跃度、板块资金流、股票搜索、评分卡、行业对比和 K 线。所有金融响应必须继续携带可用的数据时间、来源或不可用状态；数据源失败不得回退为页面演示数字。

## 垂直工作包

1. 今日观察：对齐市场数据的页面字段、时点和数据状态，补齐接口测试与失败展示。
2. 个股评分库：保留搜索、评分卡、行业对比、K 线；新增已落库资讯读取与可追溯 AI 精选读取。资讯仅返回已授权来源和安全 URL，AI 精选仅返回带来源、产生时间和状态的已审核研究内容。
3. AI 研究与我的关注：复用会话、Agent Run、自选和研究行动，补页面所需的状态、权限校验、错误路径和元数据。
4. 研究复盘与个人中心：复用用户隔离的 Run Review、研究结果和会话事实，增加真实研究资产计数和安全会话摘要；不呈现虚构的额度、收益、余额或持仓。
5. 静态演示与契约清理：所有未接入模块显示明确的不可用/未开放状态并保留空状态。移除伪支付流程；在真实订单、支付回调、对账、退款、权限和合规链路完成前，不创建支付订单也不显示“支付宝保障”或固定会员价格。

## 安全与金融数据边界

- 私人对象一律从 HttpOnly 会话解析用户身份，服务层按资源所有者过滤。
- 所有写接口使用 Pydantic/现有 Schema 校验，状态仅允许定义的枚举值。
- 新闻与链接在服务端做来源和协议白名单；不返回供应商密钥、内部 Prompt 或诊断细节。
- 估值、行情、统计和排名只由确定性服务计算，响应注明数据口径与时点。缺失、过期、供应商失败和解析失败必须可区分。
- 研究结论明确为研究材料，不构成买卖、仓位、目标价或收益承诺。

## 测试与验证

每个新增行为先写单元或 API 契约测试并确认失败，再实现最小代码。测试覆盖正常响应、空状态、数据源失败、输入校验和跨用户越权。完成后运行受影响的 pytest 模块、Ruff，以及 FastAPI 测试客户端的页面/接口契约检查。

## 兼容与迁移

本轮不删除既有接口、不修改数据库中仍被旧页面使用的字段。若需要持久化新增资讯或精选内容，将先以可重复执行的 SQLite 建表迁移方式新增结构，再通过兼容读取上线。当前工作目录不含 Git 元数据，因而无法创建 worktree 或提交；文件修改将保持可审阅且不覆盖用户已有文件。

## 失败降级

市场和股票数据调用失败时，接口返回受控错误，前端显示“真实数据暂不可用”。用户私有数据为空时显示空状态。AI、资讯和非核心聚合失败不得阻断基础行情、历史研究或自选列表读取。
