## 侦察结论（现状事实）

技术栈：纯静态 SPA——单 HTML（236 行）+ 单 CSS（85 长行，`:root` 已有 12 个设计变量）+ 两个 JS（1265+40 行），无框架、无组件库、无 Tailwind。六个页面是同一 HTML 内的六个 `<section class="page">`，`data-page` 切换。

关键事实：
1. **个人中心页的「会员/积分/API 表/账户信息」静态 HTML（html:222-223）在运行时被 `loadProfileSummary()`（js:1206）整页替换**为诚实版（「不展示虚构积分、会员或资产余额」），但首屏会闪现演示内容；且接口失败时 catch 只留错误句。
2. js:251 `if(false&&accountInfo)` —— 会员购买/立即购买区块是**永不执行的死代码**（约 18 行 JS + css:74/84 的 `.purchase-*`/`.payment-*` 死样式）。
3. 「创建订单草稿」入口（js:1207 `#profileOrderDraft`）是**活代码**，调真实接口 `POST /me/payment-orders/draft`——用户指令：隐藏该入口。
4. 今日观察页：`window.QSTodayConfig` 从未在页面设置 → `baseURL:''` → 内置示例数据兜底生效，页脚「演示数据」标注属实，须保持诚实。
5. 个人复盘页（html:178-187）整张是静态写死的示例交易记录，无 JS 接线。
6. js:802 把后端原始枚举 `available/unavailable` 直接渲染给用户（「行情 unavailable · 财务 unavailable」）。
7. js:249 关注表格 loading 行 `colspan=9`，表头实为 10 列——视觉瑕疵。

## B. 视觉统一（任务二）

**色彩决策（需确认）**：保留现有 `:root` 变量值（`--blue:#1768ef`、`--red:#f3262d`、`--green:#079a56` 等）。理由：① 现有色板本身协调专业，与用户建议基准（#2563EB 等）同族；② canvas 图表引擎色板已冻结为 #1768ef/#f3262d/#079a56（两轮评审确认），CSS 换色会与图表失同步，而 canvas 无法读 CSS 变量，同步需重构（本轮禁止）。用户基准作为**一致性检查清单**落实，不做全站换色。

集中小修（仅 CSS，值级替换）：
1. `.price-chart{cursor:zoom-in}` → `cursor:grab`（拖拽平移已落地，zoom-in 误导；激活拖拽 cursor 由 JS 控制则保留 ns-resize 放大态）
2. `.badge` 背景 `#ef2929` → `var(--red)`（与全站红统一；角标本体已在 A1 删除，此处防御性统一）
3. `.btn` 边框 `#cbd9ed` → `var(--line)`（全站 7 种近似边框灰中最大的一处偏差，向 token 收敛）

不做：不改栅格/字号体系/圆角体系（现状一致）；不加运行时依赖。
