# 正式前端后三页与共享底座设计 V1

**状态：待审阅**  
**基线：** `codex/today-runtime-fix` / `24a03c05a9bbfc145bf46dc2168e1dc83d2b24e5`  
**范围：** 共享工作台底座、个股研究、金融顾问、研究中心；透明选股作为后续独立工作包。  
**视觉依据：** 《11.pptx》第 6、7、8 页；视觉只定义信息层级与布局，不构成数据事实。

## 1. 目标与边界

目标是将已有真实后端能力以 React 正式工作台形式接通，形成六页产品中后三页的可部署实现：

| 路由 | 本轮定位 | 后端就绪度 | 可开始程度 |
| --- | --- | --- | --- |
| `/stocks/:symbol` | 个股研究的正式阅读、研究工作区与跳转入口 | 高 | 可直接实施 |
| `/advisor/:conversationId?` | 有证据的金融顾问对话、流式结果、候选写回 | 中 | UI 可开始；完整溯源需小型合同扩展 |
| `/research-center` | 研究工作流总览、变化、行动、结果与报告差异 | 中 | 只读总览可直接实施；通用决策写入需合同补齐 |

不在本轮范围：金融计算、行情供应商、历史数据回填、旧 `app/static`、透明选股页面实现、增加模拟数值、将管理端执行能力暴露给普通用户、替换框架或新增图表依赖。

所有可见数字、时间、状态、证券和结论都必须来自接口字段；缺失、过期、权限不足、部分可用与外部数据失败必须如实呈现，不能以 `0`、示例文本或“数据接入中”掩盖。

## 2. 现有事实与合同修订

### 2.1 已有可复用能力

| 能力 | 当前接口或实现 | 设计用法 |
| --- | --- | --- |
| 个股主数据 | `GET /v1/stocks/{symbol}/page?range=1y` | 报价、价格序列、财务与页面核心数据 |
| 个股图表 | `GET /stocks/{symbol}/history` | K 线/趋势图的真实历史序列；失败时只隐藏图，不阻塞基础数据 |
| 同业比较 | `GET /peer-comparisons/{symbol}` | 同业表格与相对估值，不可用时使用模块状态 |
| 研究工作区 | `GET /v1/stocks/{symbol}/workspace` 及 thesis/task/evidence/timeline 路由 | 当前观点、待办、证据与研究时间线 |
| 顾问会话 | `GET/POST /me/conversations`、`GET/PATCH/DELETE /me/conversations/{id}` | 会话侧栏、创建、重命名、删除 |
| 顾问执行 | `POST /me/chat`、`GET /me/chat/stream/{request_id}`、`GET /me/runs/{run_id}` | 消息流、SSE、运行状态与中断后的恢复 |
| AI 写回 | `GET /v1/ai-writebacks`、详情、confirm/reject | 只在用户确认后写回正式研究数据 |
| 研究中心 | `GET /me/research-changes`、`research-priority`、`research-actions`、`research-outcomes`、`run-reviews`、`evidence-tasks` | 变化、优先级、行动、结果和可追溯证据任务 |
| 研报与校准 | `GET /research-reports/{symbol}`、`GET /outlook-calibrations/{symbol}` | 报告阅读与差异摘要，不能自行推导“已复核”状态 |

### 2.2 必须遵守的合同解释

1. 当前 `/v1/stock-workspaces` 不支持服务端筛选或排序。因此 URL 中的本地筛选、排序不得进入 TanStack Query key；它们只对已返回集合作纯前端变换。只有后端真实支持的筛选、分页参数才能进入 query key。
2. 既有正式合同建议使用 ECharts，但当前工程未引入它，且本轮禁止新增依赖。先建立 `ChartContainer` 统一状态、尺寸、无障碍和 SVG 渲染接口；后续若单独批准依赖变更，再以兼容实现替换内部图表引擎。
3. 正式左侧导航只保留六页产品入口：今日观察、透明选股、我的关注、个股研究、金融顾问、研究中心。`/market-data` 不得作为正式主导航项；既有路由是否保留由后续兼容性审查决定。
4. 原型中的价格目标、资金流、收益、研究结论、候选数量和进度均不得照抄。没有真实字段便不显示该模块或显示明确的不可用状态。

## 3. 工作包 0：共享正式工作台底座

本工作包先于后三页，且不改变既有后端合同。

| 组件 | 用户问题 / 视觉锚点 | 数据与状态 | 事件 | 响应式与无障碍 |
| --- | --- | --- | --- | --- |
| `AppShell` | 稳定的左侧产品导航、顶部搜索/通知/账号 | 路由、`GET /session`、认证锁定状态 | 导航、登录、退出 | 1440/1280 固定工作台；820/390 提供可触达的折叠导航，不能仅隐藏导航 |
| `GlobalSearch` | 顶部跨页证券/功能搜索 | `/v1/search`，仅在输入后请求 | Ctrl/Cmd+K、上下选择、Enter 打开已选项 | combobox 语义、键盘可用、焦点恢复；不得默认打开首项 |
| `DataTimestamp` | 让用户知道数据何时、以何状态取得 | 每个模块已有 `as_of`、source、status 字段 | 无写入 | `time` 语义；不把未知时间伪装为当前 |
| `StatusBadge` 与 `ModuleState` | 统一空态、加载、partial、unavailable、401/403/409、stale | Query 状态与后端状态 | 重试只适用于可恢复错误 | `aria-live` 仅用于状态变化；可读文本不能只靠颜色 |
| `QueryBoundary` | 一次认证失效只走一条清理和引导链 | 全局 401 处理、受影响 query key | 清理会话与私有缓存、显示认证入口 | 不重复弹窗；保持当前 URL |
| `ChartContainer` | 图表统一高度、标题、数据状态和导出边界 | 真实序列或空序列 | tooltip/范围控制仅在真实接口支持时展示 | 图表提供摘要文本；窄屏不溢出 |
| `Drawer` / `ConfirmDialog` | 证据阅读与高风险确认不挤压主流程 | 子资源加载/提交状态 | 打开、关闭、确认、取消 | focus trap、Escape、焦点恢复、390px 可操作 |

共享 token 采用合同的浅色金融工作台口径：页面 `#F5F7FB`、卡片 `#FFFFFF`、主色 `#2F6BFF`、成功 `#18A979`、警告 `#F59E0B`、风险 `#F04438`、主文本 `#172033`。红绿只表达金融涨跌或风险事实，并同时展示符号、标签或文字。

## 4. 工作包 1：个股研究 `/stocks/:symbol`

### 4.1 页面职责

以现有 `StockResearchPage`、适配器和真实查询为数据基础，重组为可维护的正式阅读页面。页面回答三个问题：这只证券现在的真实状态是什么、当前研究观点与证据是什么、下一步可以进入哪个已有研究动作。

视觉借鉴第 6 页的“中心主图 + 右侧研究工作区 + 下方证据模块”结构，但实际字段决定模块是否出现：

1. 证券头部：标准化 symbol、名称、报价、涨跌、数据时间和来源状态；
2. 核心图表：使用真实价格历史，独立于基础报价加载；数据不足或失败时不渲染空坐标轴；
3. 当前研究工作区：已持久化 thesis、观测任务、证据、时间线；
4. 财务/估值/同业：只读真实字段，缺失时使用模块状态，不推算目标价；
5. 右侧快捷入口：进入金融顾问时携带当前 symbol；进入/创建研究工作区时使用既有路由；
6. 风险、下一检查点：仅显示由任务或持久化研究状态支持的信息。

### 4.2 数据流与交互

| 模块 | Query | 写入 / 跳转 | 失败策略 |
| --- | --- | --- | --- |
| 基础页数据 | `/v1/stocks/{symbol}/page?range=1y` | 无 | 整页真实不可用状态；不能把 symbol 解释成其他证券 |
| 价格图 | `/stocks/{symbol}/history` | 范围切换仅使用接口支持范围 | 基础内容继续显示，图表隐藏并说明数据不可用 |
| 同业 | `/peer-comparisons/{symbol}` | 跳转该 peer 的 `/stocks/:symbol` | 单模块 unavailable |
| 工作区 | `/v1/stocks/{symbol}/workspace` 与已有 thesis/task/evidence/timeline 路由 | 使用当前已有确认性写入流程 | 401/403/409 走统一边界或明确冲突提示 |

桌面使用 12 列网格：主阅读区 8–9 列，研究工作区 3–4 列；1280 缩减图表和边栏密度；820 以下将右栏按阅读优先级下沉；390 单列、横向滚动只允许在数据表容器内。

### 4.3 验收

- 基础报价不等待历史序列；
- 没有任何 PPT 示例价格、目标价或资金流；
- 证券切换不会展示上一证券的缓存内容；
- 任一模块失败不会将缺失值转换为 `0`；
- 从 `/today`、`/watchlist`、`/advisor` 进入时 symbol 可追溯；
- 1440、1280、820、390 的截图与真实会话 E2E 均通过。

## 5. 工作包 2：金融顾问 `/advisor/:conversationId?`

### 5.1 页面职责与布局

视觉以第 7 页为锚点，保持三栏但不复制虚构“六因素评分”：

| 区域 | 组件 | 真实职责 |
| --- | --- | --- |
| 左栏 | `ConversationSidebar` | 加载、创建、重命名、删除用户自己的会话；显示持久化标题和更新时间 |
| 中栏 | `ContextBar`、`MessageStream`、`ClarifyingQuestionFlow`、输入框 | 显示证券、请求状态、消息、澄清问题、SSE 增量和可恢复 run |
| 右栏 | `EvidenceDrawer`、`FiveFactorAnalysis`、`WritebackCandidateCard` | 只展示模型/后端返回且可追溯的证据、结构化分析和候选写回；没有数据则不创建评分卡 |

桌面三栏；1280 侧栏紧凑；820 将证据转为 Drawer；390 会话列表与证据均为全屏/底部 Drawer，消息流和输入框保持可访问。

### 5.2 会话与执行状态机

```text
无会话 -> 创建/选择会话 -> 提交 ChatRequest -> request_id
       -> SSE 流式中 -> completed | failed | cancelled | reconnecting
       -> 发现候选写回 -> 查看证据 -> confirm | reject
```

- 消息提交使用现有 `POST /me/chat`；流使用 `GET /me/chat/stream/{request_id}`；刷新后通过 run/status 查询恢复，而非本地伪造已完成消息。
- 一次执行只允许一个活跃 SSE 连接；断线展示可恢复状态，不能重复扣费或重复提交。
- `POST /me/chat/refine` 只在现有后端接受的上下文与 run 条件成立时使用。
- AI 结果始终是候选，不可直接改变 thesis、task、report 或用户结论；confirm/reject 必须走 `/v1/ai-writebacks` 的既有确认合同，并显示 409 版本冲突。
- 不在浏览器保存 token、Cookie、原始敏感证据或未确认写回。

### 5.3 全量来源溯源的前置合同缺口

现有 `ChatRequest` 有 `symbol`、`conversation_id`、`request_id` 等字段，但没有可持久化的 `sourcePage`、`module`、`asOf`。因此 UI 可以使用已有字段实现真实会话和 symbol 上下文，但不能诚实地宣称请求源页面、源模块和数据时点已经被服务端持久化。

完整验收前需要单独评审一个向后兼容的最小后端合同扩展：在 ChatRequest 和持久化 run metadata 中增加可选、Schema 校验的 `entry_context`（`source_page`、`module`、`as_of`、可选 `symbol`）。不允许把这些值拼进用户 message 文本。旧客户端不传时保持当前行为；新界面只在服务端回显/持久化成功后把 ContextBar 标注为“已记录来源”。

### 5.4 验收

- 会话、消息、SSE、候选写回均使用真实 authenticated API；
- 用户 A 无法看到或确认用户 B 的对象；
- 断线、401、403、409、Provider 失败都有明确状态；
- 无证据时不展示虚构的五因素评分；
- 完整“来源已持久化”验收受上述兼容合同扩展阻塞。

## 6. 工作包 3：研究中心 `/research-center`

### 6.1 页面职责与布局

视觉以第 8 页为锚点：顶部是待处理研究信号，主体是“过去判断—发生变化—当前行动”的时间逻辑，底部为报告差异、进度和结果。它不是独立金融计算器，也不生成虚构投研结论。

| 模块 | 数据来源 | 可见条件 | 行为 |
| --- | --- | --- | --- |
| 优先处理 | `/me/research-priority` | 有真实优先项 | 进入对应 stock/workspace/advisor |
| 研究变化 | `/me/research-changes` | 有可追溯变化 | 打开变更详情或关联证券 |
| 当前行动 | `/me/research-actions` | 后端返回可执行行动 | 仅展示后端提供的合法动作；跳转而非伪写入 |
| Run review | `/me/run-reviews` | 有已持久化 review | 展示 run、时间、状态、原始依据 |
| 证据任务 | `/me/evidence-tasks` | 有任务 | 使用既有任务详情/处理合同；冲突走 409 提示 |
| 研究结果 | `/me/research-outcomes` | 字段包含实际 anchor、期间、方法和状态 | 否则隐藏模块或标为 unavailable，绝不显示收益示例 |
| 研报差异 | `/research-reports/{symbol}`、`/outlook-calibrations/{symbol}` | 已选择证券且接口返回真实版本 | 打开 Reader / diff，不假设存在报告 |

“维持”“继续”“已复核”等文字只有在现有持久化状态或可追溯记录明确支持时显示。当前没有通用决策确认写回合同时，研究中心只能提供只读状态和进入既有写入工作流的入口，不能新增一个看似已保存的按钮。

桌面采用 12 列：变化时间线 6–7 列、优先/行动 3 列、结果/报告 2–3 列；820 变为两列、证据 Reader 用 Drawer；390 单列，表格单独水平滚动。

### 6.2 验收

- 每个状态都能定位到返回字段、时间和来源；
- 空数据、部分数据与无权限状态不同呈现；
- 列表有 API 的 limit/page 则采用它；无分页合同则受后端数量上限约束并明确显示；
- 不因一个报告或 outcome Provider 失败而阻断变化和行动；
- 不宣称行动或结果已保存，除非能重新读取到其持久化记录。

## 8. 风险、兼容与回滚

1. **顾问来源溯源：** 不扩展 run metadata 时，只能交付真实会话 UI，不能将来源栏标为持久化事实。扩展为可选字段，旧客户端继续工作；发生问题可停止新字段写入而不影响既有会话。
2. **研究中心决策写入：** 缺少通用持久化合同前，界面只读并链接已有工作流，避免伪造“已保存”。后续增加写入必须先定义状态机、权限、幂等键与 409 语义。
3. **图表依赖：** 保持当前 SVG，避免本轮引入 ECharts 造成构建/体积/视觉回归风险；`ChartContainer` 使后续替换局部且可回滚。
4. **路由兼容：** 仅调整正式导航，不立刻删除旧路由。任何移除需先搜索调用方、保留兼容入口并完成路由 E2E。
5. **外部数据：** Provider 失败只影响对应模块；不得变成零值、无限重试或页面崩溃。

## 9. 本规格的决策

- 个股研究可作为第一个实现页面，后端与现有前端数据适配均已具备；
- 金融顾问先实现真实会话、流式和候选写回，再单独评审最小来源元数据合同扩展；
- 研究中心先实现可追溯的只读工作流总览，不实现没有持久化支持的通用“确认决策”；
- 透明选股保留为后三页完成并稳定后开始的独立页面工作包；
- 在本规格获确认前，不修改上述页面业务代码。
