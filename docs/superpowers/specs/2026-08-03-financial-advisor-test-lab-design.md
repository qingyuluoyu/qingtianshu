# 金融顾问测试台设计说明

## 目标

在不进入完整六页工作台的情况下，提供一个独立的金融顾问测试入口。测试者可以发送真实问题、接收同一条正式对话链路的回答，并在右侧查看本轮实际采用的上下文、证据、路由判断、数据时点和安全限制，从而提出可执行的微调意见。

## 非目标

- 不替换或改写正式金融顾问页面。
- 不创建第二套提示词、检索或金融计算逻辑。
- 不向测试台暴露系统提示词全文、密钥、内部文件路径、其他用户数据或原始受限数据。
- 不允许测试请求直接写入自选、长期记忆、研究任务、交易流程或 AI 写回候选。

## 访问与部署

- 页面路径：`/advisor-lab`。
- API 路径以 `/me/advisor-lab/` 开头。
- 同一个 FastAPI 服务提供页面、API 和 SSE；本地启动只需一个端口，例如 `http://127.0.0.1:8000/advisor-lab`。
- 不需要 Vite、Node 开发服务器或第二个反向代理端口。

## 页面设计

### 左侧：测试对话

- 顶部显示“金融顾问测试台”、新建测试会话和模型档位。
- 中部只显示本测试会话的用户问题、流式进度和最终回答。
- 底部提供输入框、发送按钮和预设问题示例。
- 会话可保存并回放，但与正式金融顾问会话隔离。

### 右侧：本轮解读

默认选择最新一轮回答；用户可点选旧回答查看对应快照。

1. **问题识别**：原始问题、识别意图、证券标识、是否使用追问上下文、选择的模型档位。
2. **实际带入的背景**：实际进入本轮编排的历史消息摘要、已确认风险画像、资料库命中片段、结构化市场/财务/公告证据及各自数据时点。
3. **可用但未采用**：候选资料或数据被排除的理由，例如不相关、过期、字段缺失、权限限制或超出上下文预算。
4. **证据与缺口**：可展示来源、文档/数据版本、数据新鲜度、缺失字段、冲突和不能得出结论的边界。
5. **执行记录**：确定性工具/工作流、Agent 执行状态、模型/提示词/工具版本、耗时、调用次数和可用时的 token/成本摘要。
6. **安全边界**：本轮被禁用的写操作、输出守卫结果及风险提示。

右侧显示的是可审计、经脱敏的上下文快照，不是系统提示词全文或底层密钥配置。

## 后端契约与数据模型

### 会话隔离

新增 `conversation_mode`，枚举为 `formal` 和 `advisor_test`；历史会话默认 `formal`。`quality_scope` 继续仅表示 `user`/`evaluation`，不复用它来承载测试语义。

数据库演进采用 expand 方式：新增列默认 `formal`，新旧应用都能读取；正式页面过滤/展示逻辑保持兼容。测试会话不会出现在正式金融顾问历史中，也不会计入正式对话质量复盘。

### API

- `POST /me/advisor-lab/chat`：接收与正式聊天兼容的输入，强制 `conversation_mode=advisor_test` 和只读执行策略。
- `GET /me/advisor-lab/conversations`：仅返回当前用户的测试会话。
- `GET /me/advisor-lab/conversations/{id}`：仅返回该用户的测试会话、消息和安全快照。
- `GET /me/advisor-lab/context/{assistant_message_id}`：返回该消息对应的脱敏上下文快照。

每个接口均使用现有 session cookie 鉴权和用户维度资源校验。

### 上下文快照

每轮回答落库一个结构化、版本化快照，至少包含：

- `snapshot_version`、请求/会话/回答标识、创建时间。
- 路由结果和候选证券解析。
- 实际采用的历史消息标识与摘要。
- 资料库检索命中、所需来源、相关性、截断状态和排除理由。
- 已采用的风险画像、公开市场/财务/公告等证据的来源、版本和时点。
- 模型、提示词、Agent 流程、工具和数据版本；执行计数、耗时和成本摘要。
- 数据缺口、数据过期、守卫结果与只读策略命中记录。

快照需要在模型执行前后由真实编排链路产生，不能由前端自行推断。

## 只读测试策略

测试接口在服务端执行允许清单，不能依赖前端隐藏按钮。以下意图或副作用默认禁止：

- 自选股新增/修改。
- 长期记忆创建、确认或写回。
- 研究任务、文章生成、报告生成、异步任务创建。
- AI 候选写回确认、仓位、交易或审批操作。

被阻止的请求返回明确的“测试台已禁用该操作”说明，并记录到快照的安全边界区。纯查询、确定性计算、数据检索和受输出守卫约束的解释性回答保持可用。

## 验收标准

1. 只启动一个应用端口即可访问 `/advisor-lab` 并完成 SSE 对话。
2. 测试会话与正式会话互不可见，且只允许本人访问。
3. 每条测试回答可查看与本轮对应的脱敏上下文快照。
4. 右侧能区分“实际带入”与“可用但未采用”，并显示原因/时点。
5. 写操作在 API 层被拒绝，绕过前端也无效。
6. 正式金融顾问和既有 `/me/chat` 兼容测试通过。
7. 新增数据库迁移、接口测试、权限测试、写操作阻断测试、前端冒烟测试和单端口启动说明。

## 风险与控制

- **上下文泄露**：快照需白名单序列化和用户隔离，禁止原样保存内部 prompt/秘密配置。
- **测试与正式链路漂移**：复用当前上下文准备、证据构建和回答执行服务，只在入口和副作用策略处分流。
- **历史数据混入**：通过 `conversation_mode` 隔离，并在正式查询与质量复盘中显式过滤。
- **快照膨胀**：对资料正文使用摘要、长度上限和引用标识；保留来源、时间和截断原因。
- **数据时点误读**：每项市场/财务/公告数据展示来源、采集时间、适用日期和可用性状态。

## 人工测试路径

1. 使用同一端口打开 `/advisor-lab`，新建测试会话。
2. 分别发送市场、个股、基金和追问类问题。
3. 对比右侧“实际带入”“未采用”“证据与缺口”的内容是否符合预期。
4. 尝试“加入自选”“记住……”等写操作，确认 API 返回测试台禁用说明且正式数据未变化。
5. 回到正式金融顾问，确认测试会话不出现在其历史列表。
