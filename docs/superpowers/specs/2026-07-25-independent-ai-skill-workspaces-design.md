# AI 对话双独立 Skill 工作区设计

日期：2026-07-25

## 目标

将现有 AI 研究页面调整为两个互不触发的研究工作区：

- 左侧“老李诊股”：使用 `lao-li-trader-perspective` Skill，面向用户问题进行对话式诊股。
- 右侧“五维分析”：使用 `a_share_universal_five_dimension_skills` v7.0.0 中的基本面、行业面、估值面、技术面和风险面五个独立 Skill。

用户点击哪个工作区的运行按钮，系统只创建并执行对应工作流。右侧五维分析不读取左侧对话历史，左侧对话也不自动触发五维任务。

## 产品边界

1. 两个工作区均只接受标准化 A 股证券标识。
2. 两边拥有独立的股票输入、问题输入、运行状态和错误状态。
3. 两边可以复用同一底层行情、财务、公告和检索缓存，但不能复用用户私有对话上下文。
4. 消费者页面只展示 Skill 名称、版本、研究范围和结果，不展示完整系统提示词。
5. 本轮不增加新的评分模型，不将五维研究结果转换为伪精确评分。
6. 本轮不增加交易、支付、会员或券商能力。

## 页面结构

### 桌面端

页面主体使用左右双列布局：

- 左列约占 50%，标题为“老李诊股”。
- 右列约占 50%，标题为“五维分析”。

左列包含：

- Skill 标识和框架说明；
- 股票输入；
- 诊股问题输入；
- “开始诊股”按钮；
- 对话式结果区；
- 后续追问输入。

右列包含：

- Skill 套件名称和 v7.0.0 版本；
- 独立股票输入；
- 可选研究重点；
- “开始五维分析”按钮；
- 基本面、行业面、估值面、技术面、风险面五张结果卡；
- 每张卡独立显示等待、运行、完成、受限或失败状态。

结果正文基础字号不低于 16px，行高不低于 1.7；标题、关键判断和状态具有明确层级。页面不使用小号灰字承载关键结论。

### 移动端

小于 820px 时改为单列排列，并提供“老李诊股 / 五维分析”页内快捷切换。输入框、主要按钮和结果卡占满可用宽度，页面本身不得横向滚动。

## Skill 资产

### 老李诊股

沿用项目已有的 `ProjectSkillLoader` 和项目内可信 Skill 目录。Skill 继续执行：

`板块主线资格 → 个股硬筛选 → 评估日触发 → 基本面和估值解释 → 风险与失效条件 → 唯一关注方向`

不得生成买卖建议、目标价或收益承诺。

### 五维分析

将用户提供的 v7.0.0 Skill 包作为版本化项目资产接入，保留：

- `COMMON_RUNTIME_STANDARD.md`
- 每个维度的 `SKILL.md`
- 每个维度的 `manifest.json`
- 每个维度的 `OUTPUT_SCHEMA.json`

后端加载器按维度读取受信任文件并计算摘要。运行记录必须保存 Skill 套件版本和各维度摘要，以便审计和结果复现。

## 后端契约与数据流

### 老李诊股

1. 用户在左侧输入股票和问题。
2. 前端调用老李诊股入口。
3. 后端验证会话、资源权限和 A 股代码。
4. 后端建立证据快照并加载老李 Skill。
5. 任务持久化并快速入队。
6. Worker 执行并保存回答。
7. 前端只轮询左侧任务状态。

### 五维分析

1. 用户在右侧输入股票和可选研究重点。
2. 前端调用独立五维研究入口。
3. 后端验证会话、A 股代码和单用户并发限制。
4. 后端只建立一次股票证据快照。
5. 任务记录标记为 `five_dimension_v7`。
6. 五个维度使用同一快照、各自 Skill 和各自输出契约执行。
7. 每个维度结果独立持久化；单维失败不得伪装为整体成功。
8. 前端只轮询右侧任务状态，不读取左侧对话。

五维入口可以在内部保留审计用会话引用，但不得读取或拼接该会话消息。前端契约不要求用户先在左侧创建或发送对话。

## 状态与错误

两侧分别维护状态，禁止使用一个全局 `researchRunning` 同时控制两个入口。

允许状态：

- `idle`
- `queued`
- `running`
- `completed`
- `constrained`
- `failed`
- `cancelled`

右侧每个维度额外拥有自身状态。数据缺失、数据冲突、数据过期和供应商失败必须分别表达，不得统一显示为空。

## 兼容策略

1. 保留现有研究接口和历史运行记录读取能力。
2. 新增显式工作流字段或兼容字段，不直接删除旧字段。
3. 历史五维运行按照旧工作流读取；新运行写入 Skill 套件版本。
4. 现有老李 Skill 配置继续有效。
5. 若五维 Skill 资产缺失或摘要不匹配，后端快速失败，页面不得显示“分析完成”。

## 安全、成本与可观测性

- Skill 文件只允许从配置指定的项目目录读取，禁止用户提交任意文件路径。
- 记录 `request_id`、`run_id`、`user_id`、工作流、股票代码、Skill 版本、数据截止时间、耗时、模型用量和失败分类。
- 两侧点击分别计费和限流；未点击的工作区不创建任务、不调用模型。
- 五维共用一次证据快照，避免重复数据抓取。
- 原始提示词不返回前端，API 只返回安全的公开元数据。

## 测试与验收

1. 点击左侧仅调用老李工作流，右侧状态不变化。
2. 点击右侧仅调用五维工作流，不读取左侧消息。
3. 两侧使用不同股票时互不覆盖。
4. 五个维度均加载 v7.0.0 对应 Skill 和输出 Schema。
5. 非 A 股输入被明确拒绝。
6. Skill 资产缺失时任务失败且错误可诊断。
7. 页面正文大小、层级和对比度满足正常阅读。
8. 1440×900 下左右双列无溢出或遮挡。
9. 390×844 下单列布局、快捷切换、按钮和结果卡无溢出。
10. 受影响测试、全量测试、Python 编译和前端脚本语法检查通过。

## 回滚

页面结构和新入口可以独立回滚到旧研究页面。Skill 资产和新增兼容字段为增量内容，回滚代码时保留不会破坏旧版本。已生成的新工作流记录继续作为只读历史数据保留。
