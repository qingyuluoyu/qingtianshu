# 通用透明选股市场快照设计

## 目标

让 `/me/stock-screener` 在生产环境只读可追溯的全市场稳定快照，避免用户请求触发全市场 Tushare 扫描，并在数据尚未准备好时保持诚实的 503 状态。

## 现状与根因

`StockScreenerService._build_persisted_snapshot()` 读取 `stock_basic`、`daily`、`daily_basic` 和 `fina_indicator` 的逐数据集快照；现有后台只发布 `a_share_universe` 与 `li_zong_inputs`，不会发布这套通用筛选输入。因此隔离生产环境正确返回 503。

## 选定方案

新增一个单用途 `stock_screen_market` 快照：后台使用既有 Tushare 全市场读取逻辑生成最近完整交易日、5 日和 20 日基准数据，将已经标准化的市场行与元数据作为一个稳定版本发布。读取端优先消费该快照，保留原有逐数据集快照兼容回退。

财务字段不伪造：质量条件优先读取已有 `fina_indicator` 稳定快照；不足时仅在配置了 Tushare 的服务端按既有上限逐股补充；覆盖不足会在合同中标记 constrained。

## 运行与错误边界

- 后台任务每天执行一次，可由环境变量设置但不低于一小时。
- 失败不覆盖旧稳定快照；同步运行记录保留成功/失败和数据版本。
- 没有 Token、快照为空或覆盖率不足时，前端仍显示真实不可用状态，不填充示例候选。
- 不改变 `/me/stock-screener` 请求或响应合同。

## 验收

1. 使用假的 Tushare 客户端发布快照后，禁用实时客户端仍能运行趋势筛选。
2. 覆盖率不足时只保存不完整版本，旧稳定版本可继续读取。
3. 后台任务只在 Tushare 客户端已配置时注册；任务失败不影响其他后台任务。
4. Docker 环境中有稳定快照时 `/me/stock-screener` 返回 200；没有数据时仍是可解释的 503。
