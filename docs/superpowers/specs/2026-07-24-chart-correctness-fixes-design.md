# 图表正确性修复设计（方案 C）

- 日期：2026-07-24
- 范围：`app/static/high-fidelity-demo.js`（单文件，不改 HTML/CSS，不加新交互，不引入依赖）
- 背景：投研工作台前端图表全部为手写 canvas + CSS conic-gradient（零依赖）。审计发现 1 个正确性缺陷、1 个视觉缺陷、1 段死代码、色板不统一。本设计只做正确性修复，不做交互增强（十字光标、tooltip、拖拽平移、模块抽离均明确排除）。

## 1. MA 均线边缘修正

**问题**：`priceChart()`（约 L1088）对可见切片（12~80 根 K 线）调用 `movingAverage(rows, n)`，可见窗口左边缘之前的K线未参与计算，导致窗口左端的 MA 值偏低或缺失；缩放越小误差越大。

**方案**：
- MA5/10/20 改为对 `klineState.data` 全量计算，再按可见窗口的偏移量切片后绘制。
- 可见窗口偏移量：`offset = klineState.data.length - visibleRows.length`。
- `updateMALabels()` 不变（其入参本为全量数据，行为正确）。
- 数据不足 N 根时 MA 保持 `null` 跳过绘制（保留现有行为）。

**性能**：每次重绘多算 ≤80×3 个均值，可忽略；无需缓存。

## 2. 雷达图标签防溢出

**问题**：`radar()`（约 L1144）所有标签固定在半径 +22px、统一 `textAlign='center'` 绘制。两侧轴的长标签（如"财务稳健性"）超出画布左右边缘被裁切；顶部标签在画布较矮时贴近上边缘。

**方案**：
- 按轴角度分配水平对齐：`cos(angle) > 0.3` → `textAlign='left'`；`< -0.3` → `'right'`；否则 `'center'`。
- 用 `c.measureText(label)` 得到文本宽度，将标签锚点 x 钳制在 `[6, w - 6]`（含对齐换算后的实际文本边界）；y 钳制在 `[10, h - 10]`。
- 标签半径保持 r+22，钳制兜底。
- 两个雷达图实例（`#industryFactorRadar` 五维行业对比、`#marketReviewRadar` 市场复盘概述）共用同一 `radar()` 函数，自动同时修复。
- 退化行为：画布过小时文本仍完整绘制（贴边），不绘制超出画布的像素。

## 3. 删除死代码

- 移除 `marketLine()` 函数（约 L1148-1151）及其在 `drawAll()` 中的调用。
- 依据：`#marketLine` 元素在 `high-fidelity-demo.html` 中不存在，函数内为硬编码演示数组，从未生效。

## 4. 统一涨跌色板

**问题**：同语义颜色多套并存——下跌绿 `#079a56`（K线/sparkline）与 `#10a25d`（雷达对比系列）；主题蓝 `#1768ef` 与 MA10 的 `#2774ed`。

**方案**：在 IIFE 顶部定义常量并在 JS 图表代码中替换字面量：

| 常量 | 值 | 语义 |
|---|---|---|
| `UP_RED` | `#f3262d` | 上涨红 |
| `DOWN_GREEN` | `#079a56` | 下跌绿 |
| `FLAT_GRAY` | `#bcc3ce` | 平盘灰 |
| `PRIMARY_BLUE` | `#1768ef` | 主题蓝（含 MA10、成交额、当前公司系列） |
| `COMPARE_GREEN` | `#10a25d` | 行业中位/对比系列专用绿（与下跌绿区分语义） |

替换点：K线/sparkline/估值对比/资金流/指数卡片中的 `#f3262d`、`#079a56` 字面量；MA10 线色 `#2774ed` → `PRIMARY_BLUE`。

明确不动：
- `watchStatusColors`（关注状态语义，非涨跌）
- HTML 内联 legend 颜色（估值对比 legend 已为 `#10a25d`，与 `COMPARE_GREEN` 一致）
- `high-fidelity-demo.css`

## 错误处理

- MA：数据 < N 根 → 该段 `null`，跳过（不画断线）。
- 雷达：任意尺寸画布下标签不越界；极端小画布退化为贴边完整绘制。
- 色板：纯常量替换，无运行时风险。

1. 复用本地 uvicorn 服务打开页面；K线缩放到最小 12 根，核对 MA5 标注值与图上均线终点一致。
