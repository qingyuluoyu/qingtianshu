# 清数智算正式六页 UI 收口设计

## 目标

在不改变现有金融数据口径、认证合同和用户数据隔离的前提下，将今日观察、透明选股、我的关注、个股研究、金融顾问、研究中心统一为一套可部署、可追溯、可响应式验收的正式金融工作台。

11.pptx 是信息架构、视觉密度和交互层级的基准，不是数据来源。PPT 中的股票、价格、评分、收益、资金流和结论不得复制到产品；所有业务数字必须来自当前认证用户可访问的真实 API。

## 唯一基线策略

- 当前功能实现来源为 `codex/today-runtime-fix` 的 `48a0f99c17778ea95e369bb020bdd7ea1c12e1d3` 及其尚未提交的 Today 修改。
- 实施前先将当前工作区完整保存为安全快照，不 reset、不 clean、不丢弃文件。
- 在快照提交上创建新的隔离工作树和 `codex/formal-six-page-ui-v1` 分支。
- `codex/formal-workbench-last3` 与当前分支在 `31d2e281e9ba0c36c520d3bc2f68d3a071a01e88` 后分叉，不能整体合并。仅允许选择性复用其共享工作台组件、移动导航、语义标题、搜索与焦点管理；透明选股、金融顾问和研究中心页面不得被较小实现整体覆盖。
- 每个选择性迁移必须先比较调用合同和测试，不按提交名称推断能力。

## 约束优先级

发生冲突时按以下顺序处理：

1. 金融计算正确性、权限和真实数据合同；
2. 本规格定义的页面信息架构与状态行为；
3. 11.pptx 的视觉比例、密度、层级与交互参考；
4. 现有实现中的局部样式。

不得为了接近截图而伪造数据、把 null 转成 0、重复缩放百分数、隐藏真实错误或放宽用户隔离。

## 共享工作台

### 正式导航

正式主导航固定为六项，顺序为：

1. 今日观察 `/today`
2. 透明选股 `/screening`
3. 我的关注 `/watchlist`
4. 个股研究 `/stocks/:symbol`
5. 金融顾问 `/advisor/:conversationId?`
6. 研究中心 `/research-center`

`/market-data` 可以作为兼容路由保留，但不能出现在正式主导航。

桌面使用固定左侧导航；820px 以下使用可访问的菜单按钮打开同一份导航结构。移动端不得只隐藏导航而不提供替代入口。顶部显示语义页面标题，不显示原始 pathname。

账号区优先显示 `account` 或用户名称；只有手机号可用时显示 `masked_phone`，不得在工作台顶部展示完整手机号样式的身份值。

### 视觉系统

- 采用白色模块、浅灰蓝页面底色、蓝色主操作和细边框。
- 红绿只表达已标注的金融事实方向或风险状态，并同时提供正负号或文字。
- 桌面标题区紧凑，不使用占据大面积首屏的通用渐变 Hero。
- 1440 与 1280 保持高密度桌面工作台；820 和 390 才进入明显重排。
- 根页面不得横向溢出；只有明确的密集表格容器可以横向滚动。
- 共用 `ModuleCard`、`ModuleState`、`DataTimestamp`、`StatusBadge`、`ChartContainer` 和焦点受控对话框。

### 状态合同

每个模块必须区分：

- loading：首次真实请求进行中；
- empty：请求成功但没有业务对象；
- partial：部分字段或上游可用；
- stale：有数据但新鲜度不足；
- unavailable：供应商或合同当前不可用；
- forbidden：无资源权限；
- conflict：409 版本冲突；
- error：可重试的模块级失败。

失败不得自动变成 0、空数组或全页空白。次级模块失败不得阻塞首屏核心模块。

## 页面设计

### 今日观察

用户目标是先判断市场整体状态，再决定今天需要复核的个人研究对象。

桌面顺序：

1. 紧凑标题、市场日期、交易状态与刷新；
2. 五个指数：上证综指、深证成指、创业板指、沪深300、科创50；
3. 市场广度、两市成交额、涨跌分布；
4. 今日优先事项、板块热度和通过合同门禁的异常模块；
5. 我的关注变化、可用研报、全球市场；
6. 数据健康栏。

指数基础值不得等待 history。history 少于两个点或请求失败时只隐藏折线。数据口径长文本收进可展开说明，不直接占据卡片主体。

资金流、异动和研报必须通过候选环境真实响应、契约测试和失败隔离三个门禁；任一门禁未通过即从正式首页移除，不展示“接入中”。

### 透明选股

三种模式互斥并写入 URL：通用筛选、李总指标筛选、历史复盘/回测。

1440/1280 的通用模式采用固定三栏：

- 左侧约 260px：筛选条件；
- 中间弹性列：运行摘要、候选表格和真实命中口径；
- 右侧约 360px：当前候选、规则命中、关键指标和去向。

条件不能横向铺满整页后再把结果堆到下方。李总模式和回测模式复用相同页面骨架，但使用独立合同和状态，不混入通用结果。服务端没有分页时不得渲染假分页。

### 我的关注

页面是个人研究资产目录，不是模拟持仓收益表。桌面保留分类、列表、行情快照、研究状态和详情/下一步结构。没有关注股票时仍保留稳定的页面骨架与添加入口，但不显示示例股票、假价格或假盈亏。

### 个股研究

先解决股票页面聚合和行情加载，再按股票头部、价格图、研究判断、基本面、事件预期、个人任务和证据结构组织。行情、财务、研究空间和事件分别失败，不能因为一个供应商失败清空整页。

页面不得生成目标价、买卖建议或没有后端依据的综合评分。

### 金融顾问

1440/1280 始终保持三栏：

- 最近对话与已携带上下文；
- 对话流、澄清问题、发送输入；
- 证据、结构化分析和待确认写回。

没有回答或证据时，右栏显示明确空态，不能删除整栏。只有结构化响应提供对应字段时才显示五面分析；不得前端生成评分。SSE 最多一个活动连接，写回必须二次确认，409 后保留冲突状态并重新读取。

### 研究中心

桌面保留以下稳定框架：

1. 待复盘、判断有变化、已有结果三张摘要卡；
2. 研究股票列表；
3. 当前判断、后来变化、当前处理；
4. 下一步入口；
5. 报告变化、研究进度和历史结果。

新账号没有研究对象时，每个区域显示真实空态和建立研究资产的入口，不把整个工作区折叠成一块提示。结果只验证研究条件后来是否出现，不表达胜率或可实现收益。

## 真实验收数据

- 使用隔离 PostgreSQL 测试数据库和非 public UUID schema。
- 通过正式注册、关注、研究、对话和确认接口创建验收用户数据。
- 前端不得内置演示 fixture，Playwright 不得对认证、业务 API 或 SSE 使用 `route.fulfill`。
- 市场公共数据使用后端正常合同或后端明确的缓存/过期状态。
- 如果某种个人业务对象没有可授权的创建入口，就验证真实空态，不通过数据库手工插入伪造完成状态。

## 验收门禁

- `npm test`、`npm run build` 通过；
- 受影响后端执行 `python -m compileall -q app` 和定向契约测试；
- 真实 FastAPI、隔离 PostgreSQL、Vite/生产静态构建和 Chromium 链路通过；
- 1440x900、1280、820、390x844 均生成截图；
- 390px 有可操作主导航，根页面无横向溢出；
- console error、page error、JS/CSS 404、API 返回 React HTML 均为 0；
- Today 核心模块不能无限 loading，超过请求生命周期必须进入明确成功或错误状态；
- 每个页面分别验证加载、空、非空、部分失败和权限状态；
- PPT 对比只验收结构、密度、层级和交互，不验收其中的演示数字。

## 实施工作包

1. 保存当前状态、建立隔离分支、冻结六页合同与真实验收场景；
2. 收口共享工作台外壳、六页导航、移动菜单、令牌和公共状态组件；
3. 修复并重排今日观察与透明选股；
4. 收口我的关注与个股研究；
5. 收口金融顾问与研究中心，完成真实跨页发布验收。

## 回滚

每个工作包独立提交。若某包验收失败，回退该包提交即可；不修改数据库 schema，不改变后端金融接口，因此代码回滚不需要数据回滚。Figma 审查稿和截图均为外部设计证据，不进入生产运行依赖。
