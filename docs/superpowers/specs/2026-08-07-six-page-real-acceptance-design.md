# 六页正式前端真实验收设计

## 目标

在同源 Docker 运行环境中，用真实 FastAPI、PostgreSQL、React 生产构建和 Chromium 验收今日观察、透明选股、我的关注、个股研究、金融顾问、研究中心六页；禁止浏览器请求 mock。

## 边界

- 不新增产品页面、金融指标或假行情。
- 不改变已冻结的认证合同、SSE 事件协议或用户隔离边界。
- 不把 Provider 不可用转换为零值或示例结果。
- 浏览器测试数据只能写入 UUID 隔离 PostgreSQL schema，结束后删除该 schema。
- StepFun 未配置时，金融顾问必须呈现明确不可用状态；配置后才执行一次真实对话验证。

## 运行架构

测试运行器创建 UUID schema，启动使用该 schema 的 FastAPI 和生产 React dist。Chromium 只访问 FastAPI 的同源地址，不能启动 Vite，也不能拦截 `/auth`、`/session`、`/v1`、`/me`、`/events`、`/stocks` 或 `/research-reports` 请求。

临时注册用户 A 和用户 B。运行器只通过正式 HTTP API 创建最小用户状态，并在结束时删除 schema。每个私有资源必须用 B 的会话尝试读取或写入 A 的资源，期望得到 401、403 或 404，且不泄露 A 的内容。

## 页面验收合同

| 页面 | 正常或可读状态 | 真实降级状态 | 必须验证 |
|---|---|---|---|
| 今日观察 | `/v1/today/overview`、指数、广度、行业和个人模块独立呈现 | Provider 失败仅影响所属模块 | 登录、刷新、五指数、无横向溢出 |
| 透明选股 | 已发布快照时读取结果 | 无快照为 `snapshot_not_ready`，不得触发扫描 | 三模式切换、局部快照标识、无无限请求 |
| 我的关注 | 用户 A 的工作空间和真实空态 | 单项行情失败不清空工作空间 | 创建/读取/删除与 B 隔离 |
| 个股研究 | 页面、历史、工作空间、任务和判断按模块呈现 | 缺少工作空间为真实空态 | 深链刷新、历史 API 不被 SPA 吞掉 |
| 金融顾问 | 会话、提交、请求状态与 SSE 回答呈现 | 未配置 AI 为可解释不可用 | A/B 会话隔离；配置 AI 时验证一次真实对话 |
| 研究中心 | 变化、结果、行动、时间线和研报按模块呈现 | 没有私有研究记录为真实空态 | 确认/拒绝写回的 409 合同与 A/B 隔离 |

## 失败处理

运行器记录每个页面的网络请求、响应状态、浏览器 console/page error、资源 404 和页面截图。Provider 502/503 可作为页面模块的已知降级，但 React 崩溃、认证失效循环、API 返回 HTML、路由误吞、无限重试、横向页面溢出或用户交叉访问均为验收失败。

## 修复准则

先把失败归类为部署路由、认证会话、API 合同、用户隔离、数据 Provider、前端状态或布局问题。每个根因先写最小失败测试，再实施单一修复并复跑对应真实页面；不为测试注入产品假数据。

## 完成标准

六页均有一次无 mock 的 Chromium 访问记录；认证与刷新恢复可用；私有资源交叉访问被拒绝；正式 React 路由、API 和 SSE 分流正确；无 console/page error；每页 390px 无文档级横向溢出。未配置的外部 AI 或行情能力只能显示明确降级，不能阻塞其他页面。
