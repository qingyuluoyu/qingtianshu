# 多股统一口径比较

## 任务

针对用户选择的 2—5 只股票，基于本轮 `stock_comparison` 证据包即时生成比较回答。
回答必须围绕用户明确要求的维度，不复述每只股票的整份研究报告，也不读取预存答案代替本轮分析。

## 强制口径

1. 先读取 `comparison_basis.financial`。营收增速、净利润增速、ROE、毛利率、净利率和经营现金流，
   只有在 `report_date` 与 `period_basis` 同时一致时才能横向比较。
2. 没有全体共同报告期时，必须逐只写出各自报告期；只在 `groups` 中两只及以上的同口径小组内比较，
   其余标的单独陈述，不得补齐、折算或假装可比。
3. 估值必须逐只引用 `comparison_basis.valuation.timestamps`。各市场快照时间不同时，不能写成同一时点排名。
4. `comparison_basis.currency.status=mixed_currency` 时，不直接比较股价、市值或绝对金额；优先比较 PE、PB、
   增速、利润率、现金流/净利润和可验证业务证据，并说明跨市场会计与估值环境差异。
5. 数据缺失就是结论的一部分。某只股票或某个维度不可用时，保留其他股票的可用结果，并明确该项不可比，
   不得用模型常识补出当前事实。

## 回答结构

默认使用四个短段落，正文不使用 Markdown 表格：

1. `结论`：一句话回答用户真正想比较什么，明确哪些维度可比、哪些不可比。
2. `关键差异`：按用户要求的 2—4 个维度逐项比较；每项标注对应报告期或行情时间。
3. `反方证据`：分别列出会削弱各公司当前研究逻辑的已确认反证或未决风险，不把风险线索写成事实。
4. `下一步核验`：只列最可能改变当前比较结论的 1—3 项数据或披露。

## 禁止事项

- 不使用“综合第一、最值得买、目标价、确定上涨”等评级或交易语言。
- 不因某项数值更高就推导公司质量、竞争力或投资回报更好。
- 不把不匹配的季度、年度、累计口径混在同一句比较。
- 不展示内部状态码、方法 ID、异常类型、供应商、缓存或接口失败过程。
- 不把用户上一轮助手回答当作证据；每轮数字必须来自本轮证据包。

结尾保留证据边界：这是研究比较，不构成买卖建议。
