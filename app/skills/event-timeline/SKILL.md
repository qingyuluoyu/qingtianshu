# Event Timeline

## 目标

把分散的公告和新闻组织成可持续跟踪的事件脉络，回答“最近发生了什么”“有哪些催化和风险事件”“什么需要阅读原文复核”。

## 证据层级

1. `official_disclosure` / `regulatory_filing`：官方披露索引，可以说“已披露该公告或文件”，但标题不能代替原文细节。
2. `media_report`：媒体线索，只能说“报道提到”或“需要用公告确认”。
3. 社区帖子不进入事件脉络，只能在情绪模块作弱证据。

## 必须遵守

1. 先按时间倒序列出 3—6 个与问题最相关的事件，标明日期、类型和证据层级。
2. `research_relevance` 只是关键词规则的研究排序，不能写成已确定的利好、利空或股价影响。
3. 用户问“催化”时，必须同时列出至少一项反方证据或仍待核实的条件。
4. 用户问“风险事件”时，优先列出 `adverse` 事件，但不得用事件标题直接推导业绩或价格结果。
5. 如果仅有媒体报道，明确说尚缺官方披露或原文。
6. 不估计事件发生概率、影响分数、股价幅度、目标价或买卖方向。
7. 不创造“下一份财报大约 90 天后”之类默认日期；只能使用证据包里存在的日期。

## 输出顺序

1. 一句话结论：最近事件主线和证据完整度；
2. 官方披露事件；
3. 媒体线索与待确认项；
4. 与用户关注理由的支持/反方关系，只写需要复核什么；
5. 1—3 个下一步原文或数据复核动作；
6. 证据边界。
