## 1. 总体结论

清数智算已经不是静态演示页面，而是一套能持续运行的内部金融研究 MVP：全球与 A 股行情、透明选股、个股研究空间、个人关注、资料库、即时 Agent、判断与任务确认、持仓操作和复盘链路都已接入真实数据库与后台任务。

当前最强的部分是产品方向、证据边界、研究闭环和工程验证；最弱的部分是部分页面的信息密度、同日直接事件覆盖、巨型单体和正式生产保障。标准大盘问答已经从半分钟级、两次模型调用降到约 10 秒、一次模型调用；模型完成前约 0.3 秒即可看到本轮真实市场证据。长期会话已经支持搜索、研究类型、具体股票、同题折叠和直接继续最近研究，历史 URL 冷启动也不再等待无关行情首页全部加载。因此，内部 MVP 已具备真实研究与演示价值，但还不能按成熟互联网金融产品对外长期运营。

本次评分改为更保守的用户视角：测试通过、接口存在和受控环境可运行不再直接等同于普通用户觉得好用。分项中的后端能力仍可能高于总体架构分，但巨型单体、首次使用成本、长尾 Agent 质量和生产门槛会直接压低综合分。

## 2. 分项详细评分

### 2.1 产品定位与核心工作流：8.3 / 10

优点：

- 产品没有退化为聊天机器人或黑盒荐股榜，而是围绕“市场事实 → 研究问题 → 多维证据 → 反方证据 → 用户确认 → 后续任务 → 操作复盘”组织。
- 普通投资者常见的市场、个股、公告、财务、选股和复盘需求已经进入同一工作空间。
- Agent 生成候选，正式判断、任务、计划和复盘仍由用户确认，信任边界清晰。

扣分：

- 首次用户仍需要理解“今日观察、我的关注、个股研究、AI研究、复盘中心”的关系，缺少一个短而明确的上手路径。
- 通知、待办、研究变化和机会线索之间仍有概念重叠，需要进一步合并为更明确的处置流。

### 2.2 功能完整度：7.8 / 10

已实现：

- 中日韩美与伦敦金行情、A 股指数/广度/成交/行业结构。
- 自选股、服务器预生成研究快照、股票研究空间、六维证据、K 线、任务与历史。
- 通用透明筛选、李总严格策略、观察池、历史点时回放和 Agent 复盘入口。
- DeepSeek 式连续对话、多个历史会话、资料库、已确认记忆、图片研究入口。
- 判断、任务、持仓操作、交易复盘草稿、用户确认和归档。

主要缺口：

- 组合层面的风险暴露、行业集中度和持仓贡献仍不够完整。
- 提醒尚未形成“批量处理、延后、完成、复盘”的完整生产级收件箱。
- 市场文章和研究机会已有内容，但订阅、个性化排序和反馈学习仍较弱。

### 2.3 金融数据体系：8.0 / 10

证据：

- 领域数据使用 PostgreSQL Schema v2；运维与持久化队列使用 PostgreSQL Schema v4。
- 本轮首先观察到 54 项数据健康为 50 项健康/4 项提示。继续追查后确认，问题不是 Worker 未运行，而是健康检查把“新闻内容时间”误当成“来源最近成功轮询时间”，同时 PostgreSQL 重复抓取会因新闻唯一键冲突失败。
- 修复后真实生产库完成 A 股公告、公司新闻、股吧，以及 NVDA 的 SEC 监管文件和 Nasdaq 公司新闻重复刷新；最终数据健康为 **53 项健康/1 项提示/0 项严重错误**。唯一提示是 A 股成交额完整历史仍在积累，不是实时行情或资讯管道失败。
- 每个资讯来源现在单独保存本轮 `ok/failed`、返回条数和轮询时间；成功检查但没有新内容不会误报为故障，部分来源真实失败仍会保留提示。
- 全市场透明筛选覆盖 5,526/5,531 只 A 股；行情、市值和候选财务覆盖接近或达到 100%，估值覆盖约 72%。
- 成交额历史已排除盘前不完整快照，不再输出数量级错误的同比变化。

扣分：

- A 股成交额完整历史仍在积累。
- 同日事件“是否足以解释涨跌”仍需继续补强；来源已成功轮询不等于存在能够证明因果的新事件。
- 商业数据授权、跨源对账、分钟级长期存储和生产对象存储尚未完成。

### 2.4 金融分析与证据逻辑：8.0 / 10

优点：

- 行情、财务、现金流、股东、主营、分析师预期、行业相对、估值、公告、情绪和反方证据已形成多模块分析。
- 价格事实由确定性工具计算，Agent 负责解释和质疑；价格结果不会自动证明原判断正确。
- 李总策略严格保留规则交集，候选为空时展示真实历史信号，不为演示放宽规则。
- 输出强调事实、推断、缺口、失效条件和下一步核验，不给目标价、仓位或保证收益。

扣分：

- “为什么涨跌”的同日直接因果证据仍不够深，部分回答只能给候选驱动。
- 历史回放是近期点时样本，不是覆盖多轮市场周期、交易成本和可成交性的正式回测。

### 2.5 Agent 能力与回答质量：7.8 / 10

本轮针对标准大盘问题完成了三次真实浏览器与数据库联合验收：

- Run `666f8d72-5ec0-4e03-b287-77f244689b43`：解释 A 股普跌原因，状态 completed，数据库总耗时 14.233 秒。
- Run `124d5638-64fe-46ae-98d5-f7b40d6ad9c4`：解释成交额和涨跌家数，状态 completed，数据库总耗时 12.113 秒。
- Run `968c0c74-9e39-42ba-8a3c-52e43d37875a`：判断普跌与结构性行情，状态 completed，数据库总耗时 10.158 秒。

三次共同结果：Provider 为 DeepSeek、模型为 `deepseek-v4-pro`、标准档 `reasoning_effort=none`、均只调用一次模型、输出校验均通过。首 Token 为 2.222—3.218 秒，中位数 2.714 秒；数据库记录的首个安全片段为 2.896—4.066 秒。真实页面最终答案约在 10.246、12.205、14.540 秒出现，中位数约 12.2 秒。

回答均包含与问题匹配的价格事实、全市场广度或成交额、反方证据/证据边界和下一步核验。浏览器以约 100 毫秒间隔记录消息变化，三次都只从空的“研究中”状态切换到最终答案，没有出现一段长回答先展示、随后被另一段摘要替换。

本轮还定位并修复了两类真实误判：一是“不能直接确认新下跌趋势”被错误识别为确认下跌趋势；二是“不能直接证明资金净流入”被错误识别为声称资金净流入。全市场广度问答现在必须给出上涨家数、下跌家数和固定分类；只有用户明确询问平盘家数时才强制平盘数。此前被误判的模型原答案实际具备完整结构，修复后不再被低质量确定性摘要覆盖。

结论：标准问题已从旧 Run 的 28.7 秒首个可见内容、35.5 秒总耗时和两次模型调用，改善到三次样本均在约 10—15 秒完成、一次模型调用。由于最终答案仍需等完整校验后才展示，页面首个答案尚未稳定进入 8 秒以内；三次样本也不足以宣称正式 P95。

本轮进一步把等待过程改成确定性证据进度卡，而不是伪装成最终回答：市场问题约 58 毫秒显示路由状态、约 307 毫秒显示同日指数、全市场涨跌家数、成交额、板块与资讯数量，约 3.9 秒进入草稿校验，约 10.1 秒原位显示最终回答；个股问题约 2.05 秒显示研究重点、最近完整日线日期、模块覆盖与可追溯来源数量。进度卡始终保留，后续只更新顶部状态，因此用户在模型完成前已经知道系统实际读到了什么。

真实追问“它相对通信设备行业更强还是更弱”不再因“行业”二字误切成大盘研究。系统继承中兴通讯标的并回答中兴通讯当日 `-2.56%`、通信设备行业 `-3.54%`、相对少跌约 `0.98` 个百分点，以及行业 50 只成分股中 3 涨 47 跌。即使中间问过市场问题，也会向前恢复最近股票标的。

### 2.6 个性化、记忆和资料库：7.6 / 10

优点：

- 每位用户有独立会话、工作区、自选股、判断、任务、资料和已确认记忆。
- 股票绑定对话和历史会话可以刷新恢复；保存资料只作为证据，不直接回放为当前 AI 答案。
- 资料库区分通用资料和用户资料，可被 Agent 检索。

本轮改善：

- 全局历史列表已隐藏零消息空会话，归档入口也从含义不明的“×”改为明确文字、可访问标签和二次确认。
- 19 条真实历史对话已按“今天 / 昨天 / 最近 7 天 / 更早”分组；同一日期内完全相同标题只直接展示最新一条，旧对话按需展开，活动对话属于旧记录时会自动保持可见。
- 当前真实用户增长到 25 条有效历史会话后，桌面和移动端均可按标题或最近内容搜索，并按个股、大盘、选股、关注和其他筛选。分类使用明确题面语义优先、最近 Agent 意图辅助，不让历史误路由继续污染界面。
- 新对话页新增紧凑的“继续上次研究”入口，显示最新有效会话的标题、研究类型、消息数和更新时间；点击后复用原 conversation ID，不复制旧答案、不新建 Run，也不合并或删除历史。
- 会话列表现在公开最近明确的 `research_targets`，并在原研究类型下拉中增加具体股票选项。真实用户当前可直接筛选中兴通讯、贵州茅台、广合科技、杰瑞股份和株冶集团，不增加第二排控件。

剩余扣分：

- 当前只折叠完全相同标题，尚未做近义问题聚类、全文搜索和批量整理；缺少明确证券元数据的旧误路由会话不会被猜测归类。

### 2.7 前端信息架构与交互：7.8 / 10

优点：

- 六个一级入口已经比早期版本清晰；AI 研究页接近主流大模型产品，Enter 发送、历史会话和证据侧栏可用。
- 今日观察、我的关注和股票空间都采用事实优先、详情按需展开的方向。
- 桌面和 390px 核心页面已有仓库内浏览器门禁。

本轮发现并修复：
